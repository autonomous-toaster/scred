## Why

MITM leaf certificates generated by `CertificateGenerator` are missing the Authority Key Identifier (AKI) extension. Python's `urllib3` (used by `requests`) requires AKI to build the certificate chain, causing `SSLError: certificate verify failed: Missing Authority Key Identifier`. curl and Node.js accept the cert anyway, but Python clients are broken.

## What Changes

- Add `use_authority_key_identifier_extension = true` to `CertificateParams` in `generate_cert_signed_by_ca`
- Add README examples showing Python and Node.js usage with env-var-only configuration

## Capabilities

### New Capabilities
- `python-mitm-client`: Python clients can connect through the MITM proxy using `REQUESTS_CA_BUNDLE` env var
- `node-mitm-client`: Node.js clients can connect through the MITM proxy using `NODE_EXTRA_CA_CERTS` env var

### Modified Capabilities
- (none)

## Impact

- `crates/scred-mitm/src/mitm/tls.rs`: One-line change in `generate_cert_signed_by_ca`
- `README.md`: Add Python and Node.js examples
